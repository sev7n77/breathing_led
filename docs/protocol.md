# 呼吸灯串口协议 v1（视觉 → 电控）

### 1. 分工
*   **视觉（算法组）**：用时间算出呼吸亮度，每 20ms 发一帧当前 RGB。
*   **电控**：收到什么颜色就显示什么颜色，**不要自己做呼吸/渐变**。
*   *说明：呼吸效果在视觉端算，电控只做“把 3 个字节变成 3 路占空比”这一件事，联调出问题容易定位。*

### 2. 物理层
*   UART，**115200 8N1**（8数据位，无校验位，1停止位），无流控。
*   视觉 TX → 电控 RX，必须共地（GND连GND）。
*   视觉端设备名常见 `/dev/ttyUSB0`（USB转TTL）或 `/dev/ttyACM0`。

### 3. 帧格式：固定 4 字节
*   **单向通信**：视觉只发，电控只收，没有回包，也没有长度字段。收满 4 字节就处理。

| 偏移 | 字段 | 类型 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | header | uint8_t | 固定 `0xA5` |
| 1 | r | uint8_t | 红 0~255 |
| 2 | g | uint8_t | 绿 0~255 |
| 3 | b | uint8_t | 蓝 0~255 |

*   **说明**：本协议**不使用应用层校验码**。电控端只需在字节流中寻找 `0xA5`，然后读取其后 3 个字节作为 RGB 即可。若数据中恰好出现 `0xA5` 导致误判，下一帧（20ms后）会自动覆盖纠正，人眼无感。

### 4. 时间参数
| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 发送频率 | 50 Hz（20 ms 一帧） | 人眼 24 fps 以上就连续，50 Hz 足够且留有余量 |
| 呼吸频率 | 0.5 Hz（2 s 一个完整明暗） | 太快像闪烁，太慢像没在动 |
| 带宽 | 4 B × 50 = 200 B/s | 115200 下占 1.7% 左右，负载极低 |

### 5. 两端的约定（重要！）
1.  **启动与退出保护**：视觉端启动后先发全 0（灭灯），再进入呼吸；视觉端按 Ctrl+C 退出时会补发一帧全 0 再关串口。避免上电或退出瞬间闪瞎眼。
2.  **超时保护机制**：电控端如果**超过 200 ms 没有收到合法包**（比如视觉程序崩溃或线断了），请**直接灭灯**，不要保持最后一帧颜色，防止灯一直亮着烧坏或干扰操作。
3.  **灯珠物理顺序警告**：如果电控使用的是 WS2812 或类似自带控制芯片的灯珠，请注意其内部物理顺序通常是 **GRB**（先绿后红再蓝）。**请电控端在代码里做好映射**（把收到的 r 赋给灯珠的 R 寄存器，g 给 G，b 给 B），不要直接把这三个字节按顺序透传给灯珠，否则颜色会红绿颠倒。
